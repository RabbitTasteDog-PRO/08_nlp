# 언어 모델링 문제은행 정답 및 해설

먼저 `언어모델링복습.ipynb`의 검증 조건을 직접 통과시킨 뒤 확인하세요. 생성 문자열, 학습 전 무작위 top-k, NNLM의 세부 확률은 실행 환경과 난수 상태에 따라 달라질 수 있습니다. 이 문서는 정답 문자열을 외우기보다 계산 방향과 불변 조건을 확인하는 용도입니다.

## 1단계. 언어 모델의 공통 원리

### 문제 1

연쇄법칙은 다음과 같습니다.

```text
P(나는, 자연어를, 공부한다, <EOS> | <BOS>)
= P(나는 | <BOS>)
× P(자연어를 | <BOS>, 나는)
× P(공부한다 | <BOS>, 나는, 자연어를)
× P(<EOS> | <BOS>, 나는, 자연어를, 공부한다)
```

주어진 값의 곱은 `0.6 × 0.5 × 0.4 × 0.8 = 0.096`입니다. `<EOS>`를 포함해야 문장이 그 위치에서 끝나는 사건까지 모델링합니다. 긴 문장은 곱하는 `0~1` 사이의 항이 더 많으므로 문장 확률이 작아지는 경향이 있습니다.

### 문제 2

| 항목 | 구분 |
| --- | --- |
| 실제 다음 토큰 ID | 학습 |
| `backward()`, `optimizer.step()` | 학습 |
| 선택 토큰을 다음 문맥에 재입력 | 추론 |
| `eval()`, `no_grad()` | 추론에서 일반적으로 사용 |
| 가중치 갱신 | 학습 |
| 앞의 선택 오류가 뒤 문맥에 누적 | 자동회귀 추론 |

`from_pretrained()`는 이미 학습된 가중치를 읽는 동작입니다. 현재 코드에서 손실·역전파·optimizer step이 없다면 새 학습이 아닙니다. Teacher forcing은 학습 때 실제 이전 정답을 입력하지만, 자동회귀 추론은 모델이 직전에 고른 토큰을 입력합니다.

### 문제 3

```python
logits = torch.tensor([
    [2.0, 1.0, 0.0, -1.0],

])
vocabulary = ["공부한다", "배운다", "좋아한다", "</s>"]

probabilities = torch.softmax(logits, dim=-1)
assert torch.allclose(probabilities.sum(dim=-1), torch.ones(2))

top_probabilities, top_ids = torch.topk(probabilities, k=2, dim=-1)
top_tokens = [
    [vocabulary[token_id] for token_id in row]
    for row in top_ids.tolist()
]
```

첫 행은 약 `[0.6439, 0.2369, 0.0871, 0.0321]`, 둘째 행은 모두 `0.25`입니다. 같은 로짓은 softmax 뒤 같은 확률을 갖습니다. 로짓은 음수도 가능하고 합이 1일 필요도 없으므로 그 자체가 확률은 아닙니다.

## 2단계. N-gram 언어 모델

### 문제 7

```python
ngram_tokenized = [sentence.split() for sentence in ngram_sentences]
ngram_vocabulary = {
    token
    for sentence in ngram_tokenized
    for token in sentence
}
ngram_vocabulary.update({START_TOKEN, END_TOKEN, OOV_TOKEN})

def add_boundaries(tokens):
    normalized = [
        token if token in ngram_vocabulary else OOV_TOKEN
        for token in tokens
    ]
    return [START_TOKEN, *normalized, END_TOKEN]

train_sequences = [
    add_boundaries(tokens)
    for tokens in ngram_tokenized
]
```

수업 코퍼스의 어휘 크기는 특수 토큰을 포함해 `21`입니다. `<OOV>`는 알려지지 않은 문자열을 대신하는 유효한 어휘 ID이며 PAD와 역할이 다릅니다.

### 문제 8

```python
bigram_counts = Counter()
context_counts = Counter()

for sequence in train_sequences:
    for previous_token, next_token in zip(sequence, sequence[1:]):
        bigram_counts[(previous_token, next_token)] += 1
        context_counts[previous_token] += 1

observed_after_i = [
    (next_token, count)
    for (previous_token, next_token), count in bigram_counts.items()
    if previous_token == "나는"
]
observed_after_i.sort(key=lambda item: (-item[1], item[0]))
```

`나는` 뒤의 결과는 `자연어: 2`, `다음: 1`, `언어: 1`이며 문맥 빈도는 `4`입니다. N-gram에서는 이 빈도표가 학습된 핵심 모델입니다.

### 문제 9

```python
def bigram_probability(previous_token, next_token):
    denominator = context_counts[previous_token]
    if denominator == 0:
        return 0.0
    return bigram_counts[(previous_token, next_token)] / denominator
```

`나는` 뒤의 확률은 `자연어: 0.5`, `다음: 0.25`, `언어: 0.25`이고 합은 `1`입니다. `P(문장을 | 나는)`의 분자는 `0`, 분모는 `4`이므로 확률은 `0`입니다.

### 문제 10

```python
def sentence_probability(sentence):
    sequence = add_boundaries(sentence.split())
    probability_product = 1.0
    first_unseen = None

    for pair in zip(sequence, sequence[1:]):
        probability = bigram_probability(*pair)
        if probability == 0.0 and first_unseen is None:
            first_unseen = pair
        probability_product *= probability

    return probability_product, first_unseen
```

학습 문장의 확률은 0보다 큽니다. Held-out 문장은 `(처리를, 예측한다)`가 미관찰 전이이므로 전체 확률이 0입니다. 단어를 따로 보았는지와 두 단어의 순서를 Bigram으로 보았는지는 다른 조건입니다. 이 코퍼스는 학습 중 `<OOV>` 전이를 관찰하지 않아 OOV 치환 뒤에도 0 확률 문제가 남습니다.

### 문제 11

```python
prediction_vocabulary = sorted(
    ngram_vocabulary - {START_TOKEN}
)

def smoothed_bigram_probability(
    previous_token,
    next_token,
    k=0.1,
):
    numerator = bigram_counts[(previous_token, next_token)] + k
    denominator = (
        context_counts[previous_token]
        + k * len(prediction_vocabulary)
    )
    return numerator / denominator
```

예측 후보 수는 `20`입니다. `P_add-k(문장을 | 나는)`는 `(0 + 0.1) / (4 + 0.1×20) = 1/60 ≈ 0.016667`입니다. 미관찰 후보에 확률 질량을 주었으므로 합을 다시 1로 맞추는 과정에서 관찰 후보의 확률도 달라집니다.

### 문제 12

```python
def sentence_perplexity(sentence, use_smoothing):
    sequence = add_boundaries(sentence.split())
    log_probability_sum = 0.0
    predicted_token_count = 0

    for previous_token, next_token in zip(
        sequence,
        sequence[1:],
    ):
        probability = (
            smoothed_bigram_probability(previous_token, next_token)
            if use_smoothing
            else bigram_probability(previous_token, next_token)
        )
        if probability == 0.0:
            return math.inf
        log_probability_sum += math.log(probability)
        predicted_token_count += 1

    return math.exp(
        -log_probability_sum / predicted_token_count
    )
```

수업 코퍼스의 예상값은 다음과 같습니다.

| 문장 | smoothing 전 | smoothing 후 |
| --- | ---: | ---: |
| 학습 문장 | `1.585` | `2.240` |
| held-out 문장 | `∞` | `4.341` |
| OOV 문장 | `∞` | `42.823` |

로그를 사용하면 작은 확률을 계속 곱할 때 생기는 underflow를 줄일 수 있습니다. PPL이 낮을수록 실제 정답에 평균적으로 더 높은 확률을 주었다는 뜻입니다.

### 문제 13

핵심 반복은 다음과 같습니다.

```python
random_generator = random.Random(seed)
current_token = START_TOKEN
generated_tokens = []

for _ in range(max_tokens):
    candidates = [
        (next_token, count)
        for (previous_token, next_token), count
```

## 3단계. Feed-forward NNLM

### 문제 14

```python
CONTEXT_SIZE = 2
corpus_tokens = sorted({
    token
    for sentence in nnlm_sentences
    for token in sentence
})
index_to_word = [
    START_TOKEN,
    END_TOKEN,
    OOV_TOKEN,
    *corpus_tokens,
]
word_to_index = {
    word: index
    for index, word in enumerate(index_to_word)
}

training_examples = []
for sentence in nnlm_sentences:
    padded = [START_TOKEN] * CONTEXT_SIZE + sentence + [END_TOKEN]
    for target_position in range(CONTEXT_SIZE, len(padded)):
        context = padded[
            target_position - CONTEXT_SIZE:target_position
        ]
        target = padded[target_position]
        training_examples.append((context, target))

context_ids = torch.tensor([
    [word_to_index[token] for token in context]
    for context, _ in training_examples
], dtype=torch.long)
target_ids = torch.tensor([
    word_to_index[target]
    for _, target in training_examples
], dtype=torch.long)
```

어휘 크기는 `22`, 학습 쌍은 `56`, shape는 각각 `(56, 2)`와 `(56,)`입니다. 첫 쌍은 `[<s>, <s>] → 나는`입니다.

### 문제 15

```python
class FeedForwardNNLM(nn.Module):
    def __init__(
        self,
        vocabulary_size,
        context_size,
        embedding_dim=8,
        hidden_dim=32,
    ):
        super().__init__()
        self.embedding = nn.Embedding(
            vocabulary_size,
            embedding_dim,
        )
        self.hidden = nn.Linear(
            context_size * embedding_dim,
            hidden_dim,
        )
        self.output = nn.Linear(
            hidden_dim,
            vocabulary_size,
        )

    def forward(self, token_ids):
        embedded = self.embedding(token_ids)
        flattened = embedded.reshape(embedded.size(0), -1)
        hidden_features = torch.tanh(
            self.hidden(flattened)
        )
        return self.output(hidden_features)
```

softmax는 추론에서 확률을 확인할 때 사용합니다. 학습의 `CrossEntropyLoss`에는 `(B, V)` 로짓을 직접 전달합니다.

### 문제 16

| 계층 | shape와 원소 수 |
| --- | --- |
| Embedding weight | `(22, 8)`, `176` |
| hidden weight | `(32, 16)`, `512` |
| hidden bias | `(32,)`, `32` |
| output weight | `(22, 32)`, `704` |
| output bias | `(22,)`, `22` |
| 전체 | `1,446` |

Embedding의 토큰 ID는 행 번호입니다. 행 안의 실수는 optimizer가 갱신하는 특징값이며 빈도나 확률이 아닙니다.

### 문제 17

학습 전 top-k는 무작위 초기화와 난수 상태에 따라 달라질 수 있습니다. 반드시 확인할 불변 조건은 입력 shape `(1, 2)`, 로짓과 확률 shape `(1, 22)`, 확률 합 `1`, top-5 shape `(1, 5)`입니다. 평가 함수 안에서는 `model.eval()`과 gradient 비활성화를 사용합니다.

### 문제 18

```python
criterion = nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(
    model.parameters(),
    lr=0.03,
)
loss_history = []

model.train()
for epoch in range(1, 301):
    optimizer.zero_grad()
    logits = model(context_ids)
    loss = criterion(logits, target_ids)
    loss.backward()
    optimizer.step()
    loss_history.append(loss.item())
```

`CrossEntropyLoss`가 내부에서 log-softmax와 negative log-likelihood를 안정적으로 결합하므로 모델에서 softmax를 먼저 적용하지 않습니다. 훈련 데이터의 감소한 loss는 훈련 패턴 적합의 근거이며 validation 일반화 성능의 근거는 아닙니다.

```python
initial_embedding = (
```

### 문제 20

코퍼스에서 `[<s>, 나는]` 다음 토큰 빈도는 `자연어: 3`, `언어: 2`, `머신러닝: 1`이고 경험적 확률은 각각 `0.5`, 약 `0.3333`, 약 `0.1667`입니다. NNLM은 모든 문맥의 손실을 공유 파라미터로 함께 줄이므로 작은 데이터에서도 이 빈도와 완전히 같은 분포일 필요는 없습니다.

## 4단계. 사전학습 GPT-2 추론

전체 결과에는 입력 ID와 새 ID가 함께 있습니다. EOS로 먼저 끝날 수 있으므로 새 토큰 수는 `24` 이하입니다. `skip_special_tokens=True`는 decode 결과 문자열에서 제어 토큰을 제외하며 모델 내부 입력을 삭제하는 옵션은 아닙니다.

### 문제 26

낮은 temperature는 높은 로짓 후보에 더 집중합니다. `top_k`는 상위 고정 개수만 남기고, `top_p`는 확률 내림차순 누적합이 `p`에 도달하는 작은 집합을 남깁니다. 함께 지정하면 필터가 함께 적용됩니다. Seed와 sampling 선택이 달라져도 `optimizer.step()`이 없으므로 가중치는 바뀌지 않습니다.

### 문제 27

입력 ID가 `[x0, x1, x2, x3]`이면 비교 위치는 `[x0, x1, x2] → [x1, x2, x3]`입니다. 각 위치는 오른쪽 미래 토큰을 보지 않고 다음 토큰을 맞혀야 하므로 causal mask가 필요합니다.

| 비교 | GPT causal LM | BERT masked LM |
| --- | --- | --- |
| 보는 문맥 | 왼쪽의 앞 토큰 | 가린 위치의 왼쪽과 오른쪽 |
| 정답 | 바로 다음 토큰 | 가려진 원래 토큰 |
| 일반적 생성 | 왼쪽부터 자동회귀 생성 | 기본 Encoder 자체는 같은 방식의 순차 생성기가 아님 |

## 5단계. 종합·디버깅

### 문제 28

핵심 수정 사항은 다음과 같습니다.

1. `prediction_vocabulary`에서 `<s>`를 제외합니다.
2. 일반 확률의 분모는 `context_counts[previous_token]`입니다.
3. 일반 확률은 `bigram_count / context_count` 순서입니다.
4. 평활 분모에는 `k * len(prediction_vocabulary)`를 더합니다.
5. 평활 확률도 `numerator / denominator` 순서입니다.

```python
prediction_vocabulary = sorted(
    ngram_vocabulary - {START_TOKEN}
)

def fixed_bigram_probability(previous_token, next_token):
    denominator = context_counts[previous_token]
    if denominator == 0:
        return 0.0
    return (
        bigram_counts[(previous_token, next_token)]
        / denominator
    )

def fixed_smoothed_probability(
    previous_token,
    next_token,
    k=0.1,
):
    numerator = bigram_counts[(previous_token, next_token)] + k
    denominator = (
        context_counts[previous_token]
        + k * len(prediction_vocabulary)
    )
    return numerator / denominator
```

### 문제 29

오류는 `(B, 2, 8)`을 그대로 `Linear(8, 32)`에 넣어 위치별 출력을 만들고 있다는 점, 원하는 출력이 `(B, V)`가 아니라 `(B, 2, V)`가 된다는 점, 어휘 축이 아닌 `dim=1`에 softmax를 적용한다는 점, CrossEntropyLoss에 확률을 넣는다는 점입니다.

수정 모델은 문제 15와 같이 임베딩을 `(B, 16)`으로 flatten하고 `Linear(16, 32)`를 사용하며 최종 `(B, V)` 로짓을 반환합니다. 확률이 필요할 때의 어휘 축은 마지막 축 `dim=-1`입니다.

### 문제 30

| 비교 기준 | N-gram | Feed-forward NNLM | GPT-2 |
| --- | --- | --- | --- |
| 문맥 표현 | 최근 `N-1`개 토큰 문자열 조합 | 고정 길이 토큰 임베딩의 연결 | 여러 앞 토큰의 Transformer 표현 |

| 대표 한계 | 희소성·장기 문맥 | 고정 창·작은 데이터 과적합 | 비용·편향·환각·사실성 |
