# 문장·단어·BERT·KLUE 문제 정답 및 해설

먼저 `문장_단어_BERT_KLUE복습.ipynb`의 빈 셀을 직접 채운 뒤 비교하세요. 이 문서의 SentencePiece 예상값은 저장소에 있는 `nsmc.model`, BERT 예시는 `klue/bert-base`를 기준으로 합니다. 라이브러리·checkpoint가 바뀌면 토큰 ID와 조각은 달라질 수 있으므로 위치 대응, mask와 Tensor shape를 함께 확인하세요.

## 1. SentencePiece와 서브워드

### 문제 1. 단어 OOV와 서브워드

OOV는 **Out Of Vocabulary**, 즉 현재 어휘에 등록되지 않은 입력입니다. 단어 어휘가 `재미있다`만 알면 `재미있지만` 전체가 OOV 한 개로 바뀌어 어근 `재미있`과 연결 어미 `지만`의 정보까지 구분하지 못할 수 있습니다. 가능한 분해 예시는 `재미있 + 지만` 또는 더 작은 `재미 + 있 + 지만`입니다.

서브워드는 이미 학습한 조각을 재조합해 OOV를 줄이지만, 학습된 문자 집합이나 byte fallback으로도 표현하지 못하는 기호·문자가 있거나 조각 자체가 등록되지 않으면 UNK가 여전히 생길 수 있습니다.

### 문제 2. Unigram과 BPE

| 비교 기준 | Unigram | BPE |
| --- | --- | --- |
| 시작 상태 | 큰 후보 subword 어휘 | 보통 문자 같은 작은 단위 |
| 반복 동작 | 가능도 기여가 낮은 후보를 제거 | 빈도가 높은 이웃 pair를 병합 |
| 최종 분할 | 후보 분할 중 확률이 높은 경로 | 학습된 merge 규칙을 순서대로 적용 |

“자주 붙는 이웃 조각을 합친다”는 BPE, “많은 후보에서 도움이 적은 조각을 제거한다”는 Unigram입니다.

### 문제 3. NSMC 학습 코퍼스

```python
raw_data = pd.read_csv(TRAIN_PATH, sep="\t")
clean_data = (
    raw_data
    .dropna(subset=["document"])
    .reset_index(drop=True)
)
print("정제 전:", raw_data.shape)       # (150000, 3)
print("정제 후:", clean_data.shape)     # (149995, 3)
print(clean_data.columns.tolist())      # id, document, label

```

SentencePiece는 문자열의 반복 패턴과 조각 확률을 학습하는 비지도 tokenizer 학습이므로 감성 label이 필요 없습니다. `id`도 리뷰 내용이 아니므로 제외합니다. 학습 텍스트 파일을 새로 쓴다면 `training_documents.to_csv(..., index=False, header=False)`처럼 한 줄에 리뷰 하나만 저장합니다.

```python
sp_model = spm.SentencePieceProcessor(
```

### 문제 6. 특수 토큰 ID

```python
special_ids = {
    "PAD": sp_model.pad_id(),
    "OOV": sp_model.unk_id(),
    "BOS": sp_model.bos_id(),
    "EOS": sp_model.eos_id(),
}
expected = {"PAD": 0, "OOV": 1, "BOS": 2, "EOS": 3}
print(special_ids)
assert special_ids == expected
for name, token_id in special_ids.items():
    print(name, token_id, sp_model.id_to_piece(token_id))
```

이 모델의 조각은 `[PAD]`, `[OOV]`, `[BOS]`, `[EOS]`입니다. PAD는 없는 빈자리라 attention mask가 0이고, OOV는 실제 입력 위치이므로 mask가 1이어야 합니다. 같은 ID이면 실제 미등록 입력까지 무시하게 됩니다. 이 ID들은 학습 때 직접 지정한 값이므로 모든 SentencePiece 모델에서 같지는 않습니다.

### 문제 7. 조각과 ID 위치 대응

```python
text_7 = "영화가 재미있지만 결말은 아쉽다"
pieces = sp_model.encode(text_7, out_type=str)
token_ids = sp_model.encode(text_7, out_type=int)

```

현재 모델의 예상 결과는 다음과 같습니다.

```text
0 '▁영화가'      70
1 '▁재미있지만'  20953
2 '▁결말은'      2153
3 '▁아쉽다'      712
```

ID는 어휘 행 주소입니다. 숫자가 크다고 더 중요하거나 더 희귀하거나 의미가 큰 것은 아닙니다.

### 문제 8. `▁` 공백 경계

```python
pieces_8 = sp_model.encode(
    "오늘 영화 정말 재미있다",
    out_type=str,
)
print(pieces_8)
print([piece for piece in pieces_8 if "▁" in piece])
```

현재 모델에서는 `['▁오늘','▁영화','▁정말','▁재미있다']`입니다. `▁`는 정규화된 원문 공백 뒤 새 단어가 시작하는 경계를 보존합니다. `▁영화`는 공백 뒤 시작한 `영화`, `영화`는 앞 조각에 이어질 수 있는 내부 조각으로 읽습니다. WordPiece의 `##`는 “앞 조각에 이어짐”을 표시하고 SentencePiece의 `▁`는 “공백 뒤 시작”을 표시해 방향이 반대입니다.

### 문제 9. OOV 위치

```python
text_9 = "영화가 재미있지만 🧪 표현은 낯설다"
pieces_9 = sp_model.encode(text_9, out_type=str)
ids_9 = sp_model.encode(text_9, out_type=int)
oov_id = sp_model.unk_id()
oov_positions = [
    position
    for position, token_id in enumerate(ids_9)
    if token_id == oov_id
]
print(pieces_9)
print(ids_9)
for position in oov_positions:
    print(position, repr(pieces_9[position]), ids_9[position])
```

현재 모델에서는 `🧪`가 위치 3, ID 1입니다. Piece 출력 API가 원래 표면 문자를 보여주더라도 모델 입력 ID는 공용 OOV 1이므로 `🧪` 전용 임베딩 행을 조회하는 것이 아닙니다.

### 문제 10. Encode/decode 왕복

```python
decode_examples = [
    "아 더빙 정말 재미있다",
    "영화가 재미있지만 🧪 표현은 낯설다",
]
for original in decode_examples:
    ids = sp_model.encode(original, out_type=int)
    restored = sp_model.decode(ids)
    print({
        "original": original,
        "ids": ids,
        "restored": restored,
        "exact_match": original == restored,
    })
```

등록 조각만 쓴 첫 문장은 보통 완전히 복원됩니다. 두 번째의 OOV는 공용 미등록 기호 `⁇` 등으로 복원되어 원문과 달라질 수 있습니다. Normalizer가 공백·호환 문자를 통일한 경우도 완전 일치하지 않을 수 있습니다. `decode()`는 토큰 ID를 문자열로 되돌리는 tokenizer 역변환이지 신경망의 의미 예측을 취소하는 연산이 아닙니다.

### 문제 11. 오른쪽 패딩과 잘림

```python
sentences_11 = [
    "재미있다",
    "영화가 정말 재미있다",
    "영화가 재미있지만 중간 이야기가 너무 길고 마지막 결말은 아쉬웠다",
]
max_length = 12
pad_id = sp_model.pad_id()
padded_ids = []

for sentence in sentences_11:
    original_ids = sp_model.encode(sentence, out_type=int)
    was_truncated = len(original_ids) > max_length
    row = original_ids[:max_length]
    row += [pad_id] * (max_length - len(row))
    padded_ids.append(row)
    print(len(original_ids), was_truncated, row)

assert all(len(row) == max_length for row in padded_ids)
```

원본 토큰 수는 현재 모델에서 직접 출력해 확인합니다. 잘림 여부는 padding 후 길이가 아니라 자르기 전 `len(original_ids) > 12`로 판단해야 합니다.

### 문제 12. Attention mask

```python
attention_mask = [
    [0 if token_id == pad_id else 1 for token_id in row]
    for row in padded_ids
]
for row, mask in zip(padded_ids, attention_mask):
    print(row)
    print(mask, "유효 위치:", sum(mask))

oov_id = sp_model.unk_id()
for row, mask in zip(padded_ids, attention_mask):
    for token_id, mask_value in zip(row, mask):
        if token_id == oov_id:
            assert mask_value == 1
```

OOV는 실제 입력이므로 1이고 PAD만 0입니다. Mask 합은 잘림 후 모델이 읽을 실제 token 수이며, ID의 각 위치와 일대일 대응해야 하므로 두 shape가 같습니다.

### 문제 13. 패딩 불변 조건

```python
assert len(padded_ids) == len(attention_mask) == 3

    assert set(mask) <= {0, 1}

```

## 2. WordPiece와 KLUE BERT

### 문제 15. 단어 UNK와 WordPiece

```python
from transformers import AutoModel, AutoTokenizer

word_vocab = {"영화가", "재미", "있다"}
text_15 = "영화가 재미있다"
word_level_tokens = [
    token if token in word_vocab else "[UNK]"
    for token in text_15.split()
]
tokenizer = AutoTokenizer.from_pretrained(MODEL_NAME)
wordpiece_tokens = tokenizer.tokenize(text_15)
print(word_level_tokens)
print(wordpiece_tokens)
```

단어 단위 결과는 `['영화가','[UNK]']`, 현재 KLUE tokenizer는 `['영화','##가','재미있','##다']`입니다. 단어 전체가 없어도 등록된 더 작은 조각으로 분해해 정보를 보존합니다.

### 문제 16. WordPiece `##`

```python
pieces_16 = tokenizer.tokenize("영화가 재미있다")
continuations = [
    piece for piece in pieces_16 if piece.startswith("##")
]
print(pieces_16, continuations)
```

`영화`, `##가`는 공백으로 분리된 두 독립 단어가 아니라 한 어절의 첫 조각과 이어지는 조각입니다. `##`는 원문 문자가 아니라 tokenizer 어휘의 경계 표기입니다. SentencePiece `▁`는 새 공백 단위 시작, WordPiece `##`는 앞 조각에 이어짐을 표시합니다.

### 문제 17. 조각과 ID 왕복

```python
token_ids_17 = tokenizer.convert_tokens_to_ids(pieces_16)
for position, (piece, token_id) in enumerate(zip(
    pieces_16, token_ids_17
)):
    print(position, piece, token_id)
restored_pieces = tokenizer.convert_ids_to_tokens(token_ids_17)
print(restored_pieces)
assert restored_pieces == pieces_16
```

현재 checkpoint의 예상 대응은 `영화:3771`, `##가:2116`, `재미있:6001`, `##다:2062`입니다. Token ID는 BERT 입력 임베딩 행렬에서 조회할 행 번호입니다.

### 문제 18. BERT 특수 토큰

```python
special_tokens = ["[PAD]", "[UNK]", "[CLS]", "[SEP]", "[MASK]"]
special_token_ids = dict(zip(
    special_tokens,
    tokenizer.convert_tokens_to_ids(special_tokens),
))
print(special_token_ids)
```

KLUE BERT에서는 각각 `0,1,2,3,4`입니다.

| 토큰 | 역할 |
| --- | --- |
| `[PAD]` | 배치 길이를 맞추는 빈자리 |
| `[UNK]` | 어휘로 표현하지 못한 실제 입력 |
| `[CLS]` | 문장 분류의 대표 위치로 사용할 수 있는 시작 토큰 |
| `[SEP]` | 문장 끝 또는 문장 쌍 경계 |
| `[MASK]` | Masked LM 사전학습에서 원래 토큰을 맞힐 위치 |

ID는 checkpoint 어휘 설계에 따라 달라질 수 있어 다른 모델에서도 같다고 보장할 수 없습니다.

### 문제 19. 두 mask 비교

```text
tokens:              [CLS] 영화 ##가 [SEP] [PAD] [PAD]
attention_mask:         1    1    1     1     0     0
special_tokens_mask:    1    0    0     1     1     1
```

`[CLS]`, `[SEP]`는 모델이 실제로 읽어 문장 대표·경계 역할을 하므로 attention mask가 1입니다. PAD는 특수 토큰이라 special mask는 1이지만 내용 없는 자리라 attention mask는 0입니다. `[MASK]`는 입력 어휘에 있는 토큰이고 `attention_mask`는 각 위치를 읽을지 정하는 별도 배열입니다. BERT 순전파에 직접 전달하는 것은 `attention_mask`입니다.

### 문제 21. PyTorch 배치

```python
batch_texts = [
```

세 모델 입력 Tensor의 dtype은 ID·mask를 담는 `torch.int64`이고 shape는 모두 `(2,12)`입니다.

### 문제 22. 문장 쌍과 `token_type_ids`

```python
pair_encoding = tokenizer(
```

### 문제 23. 길이 8과 잘림

```python
batch_encoding_8 = tokenizer(

for index, text in enumerate(batch_texts):
```

### 문제 24. Checkpoint 정렬

```text
문자열
→ (tokenizer)
→ input ID
→ (BERT 입력 embedding matrix)의 해당 행
→ token embedding
```

Tokenizer와 모델은 같은 어휘 문자열→ID 대응을 공유해야 합니다. 서로 다른 checkpoint를 섞으면 숫자 3771이 한 tokenizer에서는 `영화`, 다른 모델에서는 전혀 다른 조각 행일 수 있으며 shape 오류 없이 잘못된 벡터를 조회해 더 위험합니다.

### 문제 25. Train·eval·inference

```python
bert_model = AutoModel.from_pretrained(MODEL_NAME)
bert_model.eval()

model_inputs_25 = {
    key: batch_encoding[key]
    for key in ("input_ids", "attention_mask", "token_type_ids")
}
with torch.inference_mode():
    outputs_25 = bert_model(**model_inputs_25)

# 미세조정 학습을 다시 시작할 때
bert_model.train()
```

`eval`은 evaluation의 약칭입니다. `eval()`은 Dropout을 끄는 등 계층 모드를 평가용으로 바꾸지만 gradient 기록을 자동으로 끄지는 않습니다. `inference_mode()`는 gradient graph와 관련 overhead를 제거해 순수 추론의 메모리·속도를 개선합니다. 미세조정 시 `train()`으로 되돌립니다.

### 문제 26. BERT 출력 shape

```python
model_inputs = {
    key: batch_encoding[key]
    for key in ("input_ids", "attention_mask", "token_type_ids")
}
bert_model.eval()
with torch.inference_mode():
    bert_outputs = bert_model(**model_inputs)
last_hidden_state = bert_outputs.last_hidden_state
print(last_hidden_state.shape)  # (2, 12, 768)
print(bert_model.config.hidden_size)  # 768
```

축은 `(배치 문장 수, 토큰 위치 수, 위치별 hidden 특성 수)`입니다. 768은 문장마다 바뀌는 값이 아니라 `klue/bert-base` 구조에 고정된 `hidden_size`이며, 각 위치의 768개 실수 값만 입력 문맥에 따라 바뀝니다.

### 문제 27. `[CLS]` 벡터

```python
cls_vectors = last_hidden_state[:, 0, :]
print(cls_vectors.shape)
assert cls_vectors.shape == (2, 768)
```

입력 전 `[CLS]`는 정수 ID 2이고, BERT 통과 후 `[CLS]`는 모든 층에서 문맥과 상호작용한 768차원 벡터입니다. 그 자체는 긍정·부정 로짓이 아닙니다. `Linear(768,2)` 같은 분류 head를 붙이고 label로 head와 필요하면 BERT까지 미세조정해야 합니다.

### 문제 28. Self-Attention과 문맥 벡터

금융 문장의 `은행` 위치는 `돈`, `찾았다` 같은 토큰을, 열매 문장의 `은행`은 `가을`, `열매`, `주웠다` 같은 토큰을 attention으로 반영하므로 같은 표면형도 다른 출력 벡터가 될 수 있습니다. Self-Attention은 모든 토큰을 같은 비율로 평균하지 않고 query-key 점수, mask와 학습된 projection에 따라 위치별 가중치가 다릅니다.

쉽게 말하면 각 단어가 문장의 다른 단어들을 살펴보고 “이 문장에서는 내가 어떤 뜻인가”에 맞게 자기 메모를 다시 쓰는 과정입니다. Word2Vec은 기본적으로 단어 유형마다 한 정적 벡터를 주고, BERT는 같은 토큰도 문장 위치·문맥마다 다른 벡터를 냅니다.

### 문제 29. Mask 평균 풀링

```python
float_mask = (
    batch_encoding["attention_mask"]
    .unsqueeze(-1)
    .to(last_hidden_state.dtype)
)
masked_hidden = last_hidden_state * float_mask
valid_counts = float_mask.sum(dim=1).clamp(min=1)
mean_vectors = masked_hidden.sum(dim=1) / valid_counts
print(float_mask.shape)   # (2, 12, 1)
print(mean_vectors.shape) # (2, 768)
```

`[CLS]` 선택은 대표 위치 하나를 쓰고, mask 평균은 `[CLS]`, `[SEP]`를 포함한 모든 유효 위치를 평균합니다. 둘은 서로 다른 문장 pooling 전략이며 downstream validation으로 선택합니다. 특수 토큰까지 제외하려면 special tokens mask를 추가로 적용해야 합니다.

### 문제 30. 문자열에서 분류 로짓까지

```python
new_texts = [
    "영화가 정말 재미있다",
    "결말이 지루하고 아쉽다",
]
encoded_30 = tokenizer(
    new_texts,
    padding="max_length",
    truncation=True,
    max_length=16,
    return_tensors="pt",
)
inputs_30 = {
    key: encoded_30[key]
    for key in ("input_ids", "attention_mask", "token_type_ids")
}

bert_model.eval()
with torch.inference_mode():
    hidden_30 = bert_model(**inputs_30).last_hidden_state
    cls_30 = hidden_30[:, 0, :]

classification_head = nn.Linear(768, 2)
logits_30 = classification_head(cls_30)
print(encoded_30["input_ids"].shape)  # (2, 16)
print(hidden_30.shape)                # (2, 16, 768)
print(cls_30.shape)                   # (2, 768)
print(logits_30.shape)                # (2, 2)
```

전체 흐름은 다음과 같습니다.

```text
문자열 2개
→ WordPiece 조각
→ [CLS]/[SEP]/[PAD]를 포함한 input_ids (2,16)
→ attention_mask·token_type_ids (2,16)
→ BERT last_hidden_state (2,16,768)
→ CLS 문장 벡터 (2,768)
→ 분류 로짓 (2,2)
```

분류 head는 무작위 초기화 상태라 두 로짓이 감성과 연결되도록 학습된 적이 없습니다. 실제 예측으로 사용하려면 label이 있는 train 데이터로 학습하고 validation/test로 평가해야 합니다.

직접 SentencePiece를 학습하면 현재 코퍼스에 맞는 새 어휘·ID 체계를 만들지만 그 ID에 맞는 downstream 임베딩 모델도 함께 학습해야 합니다. KLUE BERT의 WordPiece를 사용할 때는 이미 사전학습된 BERT 가중치와 정확히 정렬된 기존 어휘·ID를 그대로 사용한다는 점이 가장 큰 차이입니다.
