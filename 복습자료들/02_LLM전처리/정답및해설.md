# LLM 전처리 문제 정답 및 해설

먼저 `전처리복습.ipynb`의 빈 셀을 직접 채운 뒤 비교하세요. NLTK·KSS·형태소 분석기 버전에 따라 세부 분리 결과가 조금 달라질 수 있으므로, 결과 문자열뿐 아니라 정제 순서와 불변 조건도 확인하는 것이 중요합니다.

## 문제 1. 영어 문장 토큰화

```python
from nltk.tokenize import sent_tokenize

review_text = (
    "Dr. Lee studies NLP at SK AI. "
    "He likes tokenization! "
    "Does he use Python?"
)

sentences = sent_tokenize(review_text)
for index, sentence in enumerate(sentences, start=1):
    print(f"{index}. {sentence}")
print("문장 수:", len(sentences))
```

예상 문장 수는 `3`입니다. Punkt 계열 문장 토크나이저는 마침표만 보고 자르는 것이 아니라 `Dr.` 같은 약어도 고려하므로 `Dr.` 뒤를 문장 경계로 잘못 판단하지 않습니다. NLTK 데이터가 없다면 먼저 `nltk.download("punkt_tab")` 또는 설치 버전에 맞는 Punkt 리소스가 필요할 수 있습니다.

## 문제 2. 단어 토큰과 문자 토큰 비교

```python
from nltk.tokenize import word_tokenize

word_tokens = word_tokenize(review_text)
character_tokens = list(review_text)

print(word_tokens, len(word_tokens))
print(character_tokens, len(character_tokens))
print("공백 포함:", " " in character_tokens)
```

`word_tokenize()`는 단어와 구두점을 토큰으로 나누지만, `list()`는 공백과 구두점을 포함해 문자열의 문자 하나하나를 원소로 만듭니다. 따라서 문자 토큰 목록에는 `' '`가 포함됩니다.

## 문제 3. 한국어·영어 혼합 문장의 문장 토큰화 비교

```python
import kss
from nltk.tokenize import sent_tokenize

mixed_text = (
    "오늘 NLP study를 시작했다. "
    "I will train a tokenizer tomorrow! "
    '"이 모델 supports Korean and English?"라고 민지가 물었다. '
    "답은 Yes, it does."
)

nltk_sentences = sent_tokenize(mixed_text)
kss_sentences = kss.split_sentences(mixed_text)

for name, result in (
    ("NLTK", nltk_sentences),
    ("KSS", kss_sentences),
):
    print(f"\n{name}: {len(result)}문장")
    for index, sentence in enumerate(result, start=1):
        print(f"{index}. {sentence}")
```

NLTK는 영어 구두점과 약어 규칙에, KSS는 한국어 종결 표현과 인용문 뒤 조사·서술부에 더 초점을 둡니다. 특히 `"…?"라고 민지가 물었다.`는 물음표만으로 문장이 끝난 것이 아니므로 KSS가 하나의 인용 포함 문장으로 유지할 가능성이 큽니다. 정확한 출력은 라이브러리 버전에 따라 달라질 수 있으므로 두 결과와 문장 수를 함께 기록합니다.

## 문제 4. 텍스트 정제와 정규화

```python
import re
import unicodedata

raw_text = (
    "ＡＩ   모델은 A.I.와 ai를 포함한다. 문의는 user@example.com, "
    "자세한 내용은 https://example.com/event 에서 확인하세요.\t"
)
term_mapping = {"A.I.": "AI", "ai": "AI", "ＡＩ": "AI"}

# 정규화: 호환 문자를 기준 문자로 통일
normalized = unicodedata.normalize("NFKC", raw_text)

# 정규화: 더 긴 표현부터 기준 용어로 치환
for source in sorted(term_mapping, key=len, reverse=True):
    normalized = normalized.replace(source, term_mapping[source])

# 정제: 민감 정보와 URL을 의미 보존용 토큰으로 마스킹
cleaned = re.sub(
    r"https?://[^\s,]+(?<![.!?])",
    "__URL__",
    normalized,
)
cleaned = re.sub(
    r"\b[\w.+-]+@[\w.-]+\.[A-Za-z]{2,}\b",
    "__EMAIL__",
    cleaned,
)

# 정제: 공백·탭 통합
cleaned = re.sub(r"\s+", " ", cleaned).strip()
print(cleaned)
```

예상 결과의 핵심은 모든 AI 표기가 `AI`가 되고, 이메일·URL이 각각 `__EMAIL__`, `__URL__`로 바뀌며 연속 공백이 사라지는 것입니다. 정규화는 같은 대상을 같은 표기로 맞추고, 정제는 분석에 불필요하거나 민감한 부분을 제거·마스킹합니다. 실제 서비스에서는 마스킹 순서와 URL 끝 구두점 규칙을 테스트 케이스로 고정해야 합니다.

## 문제 5. 어간 추출과 표제어 추출

```python
from nltk.stem import PorterStemmer, WordNetLemmatizer

words = [
    "runs", "running", "ran", "studies",
    "studying", "better", "flies",
]
stemmer = PorterStemmer()
lemmatizer = WordNetLemmatizer()

verb_words = {"runs", "running", "ran", "studies", "studying", "flies"}

for word in words:
    default_lemma = lemmatizer.lemmatize(word)
    pos = "a" if word == "better" else "v" if word in verb_words else "n"
    pos_lemma = lemmatizer.lemmatize(word, pos=pos)
    print(word, stemmer.stem(word), default_lemma, pos_lemma)
```

대표적인 결과는 `ran → run`(동사 지정), `better → good`(형용사 지정)입니다. Porter stem은 `studies → studi`, `flies → fli`처럼 실제 사전에 없는 문자열을 만들 수 있습니다. Lemmatizer는 품사 없이 호출하면 기본적으로 명사로 간주하므로, 올바른 표제어를 얻으려면 문맥에 맞는 품사가 중요합니다.

## 문제 6. 정규표현식 탐색·추출·치환

```python
import re

log_text = (
    "2026-07-27 user@example.com ordered item A-102 for 19,900원. "
    "문의: 010-1234-5678, URL: https://shop.example.com/A-102"
)

patterns = {
    "date": r"\b\d{4}-\d{2}-\d{2}\b",
    "email": r"\b[\w.+-]+@[\w.-]+\.[A-Za-z]{2,}\b",
    "phone": r"\b01[016789]-\d{3,4}-\d{4}\b",
    "item": r"\b[A-Z]-\d{3}\b",
    "url": r"https?://[^\s,]+(?<![.!?])",
}

for name, pattern in patterns.items():
    print(name, re.findall(pattern, log_text))

masked = re.sub(patterns["email"], "__EMAIL__", log_text)
masked = re.sub(patterns["phone"], "__PHONE__", masked)
print(masked)
```

`re.search()`는 첫 일치 객체를, `re.findall()`은 모든 일치 문자열을, `re.sub()`는 일치 부분을 치환한 문자열을 반환합니다. 마스킹 뒤에도 날짜·상품 코드·가격·URL은 그대로 남아야 합니다. URL 패턴의 끝 조건은 문장 끝 마침표를 URL에 포함하지 않도록 하기 위한 것입니다.

## 문제 7. 정수 인코딩과 패딩

```python
from collections import Counter
import numpy as np

tokenized_sentences = [
    ["little", "prince", "travels", "home"],
    ["little", "prince", "meets", "a", "pilot"],
    ["the", "pilot", "writes", "a", "story"],
]
new_sentence = ["little", "prince", "visits", "mars"]

counts = Counter(
    token
    for sentence in tokenized_sentences
    for token in sentence
)
top_tokens = sorted(
    counts,
    key=lambda token: (-counts[token], token),
)[:8]

word_to_id = {"<PAD>": 0, "<OOV>": 1}
word_to_id.update({
    word: index
    for index, word in enumerate(top_tokens, start=2)
})
id_to_word = {index: word for word, index in word_to_id.items()}

def encode(tokens):
    return [
        word_to_id.get(token, word_to_id["<OOV>"])
        for token in tokens
    ]

def pad_or_truncate(ids, max_length=6):
    ids = ids[:max_length]
    return ids + [word_to_id["<PAD>"]] * (max_length - len(ids))

encoded_sequences = [
    encode(sentence)
    for sentence in [*tokenized_sentences, new_sentence]
]
padded_sequences = np.array([
    pad_or_truncate(ids)
    for ids in encoded_sequences
], dtype=np.int64)

print(counts)
print(word_to_id)
print(encoded_sequences)
print(padded_sequences, padded_sequences.shape)
assert encode(new_sentence)[-2:] == [1, 1]
```

동률을 알파벳순으로 정렬했으므로 상위 어휘는 `a, little, pilot, prince, home, meets, story, the`입니다. `visits`, `mars`뿐 아니라 상위 8개에서 밀려난 학습 토큰도 현재 제한 어휘에서는 OOV가 됩니다. PAD는 실제 입력이 아닌 빈자리이고 OOV는 실제로 있었지만 사전에 없는 토큰이므로 서로 다른 ID여야 합니다.

## 문제 8. 원-핫 인코딩

```python
import torch
import torch.nn.functional as F

id_tensor = torch.tensor(padded_sequences, dtype=torch.long)
X = F.one_hot(
    id_tensor,
    num_classes=len(word_to_id),
)

print("shape:", X.shape)
for position, token_id in enumerate(id_tensor[0].tolist()):
    token = id_to_word[token_id]
    hot_column = int(X[0, position].argmax())
    print(position, token, token_id, hot_column)

zero_ratio = (X == 0).float().mean().item()
print("0 비율:", zero_ratio)
```

Shape는 `(문장 수, 6, 어휘 수)`입니다. 정수 ID는 행을 찾는 번호일 뿐이어서 ID 차이가 의미 거리나 순서를 뜻하지 않습니다. 원-핫은 서로 다른 두 단어의 내적이 항상 0이고, 어휘가 커질수록 대부분이 0인 매우 큰 희소 벡터가 된다는 한계가 있습니다.

## 문제 9. 한국어 명사 빈도와 워드클라우드

```python
import re
from collections import Counter
from pathlib import Path

import matplotlib.pyplot as plt
import pandas as pd
from konlpy.tag import Okt
from wordcloud import WordCloud

korean_corpus = (
    "서울 카페에서 커피를 마셨다. 서울 카페는 조용한 카페였다. "
    "친구와 서울 공원에서 산책하고 커피를 마셨다. "
    "https://example.com 이벤트 정보와 광고 문구는 제외한다."
)
domain_stopwords = {"정보", "문구", "이벤트", "광고"}

cleaned = re.sub(r"https?://\S+", " ", korean_corpus)
cleaned = re.sub(r"\s+", " ", cleaned).strip()

nouns = Okt().nouns(cleaned)
filtered_nouns = [
    noun
    for noun in nouns
    if len(noun) > 1 and noun not in domain_stopwords
]
frequencies = Counter(filtered_nouns)

frequency_df = pd.DataFrame(
    frequencies.most_common(10),
    columns=["noun", "count"],
)
print(frequency_df)

frequency_df.sort_values("count").plot.barh(
    x="noun",
    y="count",
    legend=False,
)
plt.tight_layout()
plt.show()

font_candidates = [
    Path("/System/Library/Fonts/AppleSDGothicNeo.ttc"),
    Path("/usr/share/fonts/truetype/nanum/NanumGothic.ttf"),
    Path("C:/Windows/Fonts/malgun.ttf"),
]
font_path = next(
    (str(path) for path in font_candidates if path.exists()),
    None,
)
if font_path is None:
    raise FileNotFoundError("사용 가능한 한글 글꼴 경로를 지정하세요.")

cloud = WordCloud(
    font_path=font_path,
    background_color="white",
    width=900,
    height=500,
).generate_from_frequencies(frequencies)

plt.figure(figsize=(10, 5))
plt.imshow(cloud, interpolation="bilinear")
plt.axis("off")
plt.show()
```

예상 상위 명사는 `서울`, `카페`, `커피`입니다. 실제 형태소 결과는 KoNLPy 사전 버전에 따라 조금 달라질 수 있습니다. 워드클라우드는 크기로 빈도를 직관적으로 보여주지만 정확한 수치 차이, 단어가 쓰인 문맥, 단어 사이 관계는 보여주지 못하므로 빈도표와 원문 검토를 함께 사용해야 합니다.
