아래 코드는 노트북 첫 셀의 import에 더해 필요한 클래스를 해당 문제에서 import한다고 가정합니다.

## 문제 1. BoW와 DTM 읽기

```python
import pandas as pd
from sklearn.feature_extraction.text import CountVectorizer

documents = [
    "I love my dog",
    "I love my cat",
    "my dog loves a walk",
    "a cat sleeps",
]

vectorizer = CountVectorizer()
bow_matrix = vectorizer.fit_transform(documents)
features = vectorizer.get_feature_names_out()
dtm_df = pd.DataFrame(
    bow_matrix.toarray(),
    index=[f"doc{i}" for i in range(1, 5)],
    columns=features,
)

print(dtm_df)
print(dtm_df.shape)                 # (4, 7)
print(dtm_df.loc["doc3", ["dog", "walk"]])  # 둘 다 1

reordered = vectorizer.transform(["dog my love I"])
print(np.array_equal(reordered.toarray(), bow_matrix[0].toarray()))
```

기본 `CountVectorizer`는 한 글자 토큰 `I`, `a`를 제외하므로 어휘는 `cat, dog, love, loves, my, sleeps, walk`입니다. DTM의 행은 문서, 열은 어휘이며 순서를 바꾼 문장은 같은 빈도 벡터가 됩니다.

## 문제 2. DTM과 TDM의 축 바꾸기

```python
tdm_df = dtm_df.T
```

전치는 값을 재계산하지 않고 행과 열을 맞바꿉니다. 따라서 DTM을 문서 관점으로, TDM을 단어 관점으로 읽을 뿐 해당 빈도는 동일합니다.

## 문제 3. TF-IDF와 문서 유사도

```python
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

tfidf_vectorizer = TfidfVectorizer()
tfidf_matrix = tfidf_vectorizer.fit_transform(documents)
tfidf_features = tfidf_vectorizer.get_feature_names_out()
tfidf_df = pd.DataFrame(
    tfidf_matrix.toarray(),
    index=dtm_df.index,
    columns=tfidf_features,
)

idf_by_word = dict(zip(tfidf_features, tfidf_vectorizer.idf_))
print({word: idf_by_word[word] for word in ("cat", "dog", "my")})

bow_similarity = cosine_similarity(bow_matrix)
tfidf_similarity = cosine_similarity(tfidf_matrix)
for i, j in ((0, 1), (0, 2)):
    print(i + 1, j + 1, bow_similarity[i, j], tfidf_similarity[i, j])

print(np.linalg.norm(tfidf_matrix.toarray(), axis=1))
assert np.allclose(
    np.linalg.norm(tfidf_matrix.toarray(), axis=1),
    np.ones(4),
)
```

`cat`, `dog`은 각각 두 문서, `my`는 세 문서에 나타나므로 `my`의 IDF가 더 낮습니다. 기본 TF-IDF 출력은 행별 L2 정규화되어 norm이 1입니다. TF-IDF는 흔한 단어의 영향은 낮추지만 여전히 단어 순서와 문맥 의미는 직접 표현하지 않습니다.

## 문제 5. Skip-gram Word2Vec과 OOV

```python
from gensim.models import Word2Vec

base_sentences = [
    ["king", "is", "a", "royal", "man"],
    ["queen", "is", "a", "royal", "woman"],
    ["prince", "is", "a", "young", "royal"],
    ["apple", "is", "a", "sweet", "fruit"],
]
sentences = base_sentences * 200

model = Word2Vec(
    sentences=sentences,
    vector_size=20,
    window=2,
    min_count=1,
    sg=1,
    epochs=100,
    seed=42,
    workers=1,
)
print(model.wv.key_to_index)
print(model.wv.vectors.shape)
print(model.wv["king"].shape)       # (20,)
print("king-queen:", model.wv.similarity("king", "queen"))
print("king-apple:", model.wv.similarity("king", "apple"))
print("kings 등록:", "kings" in model.wv.key_to_index)
```

일반 Word2Vec은 등록 단어마다 벡터 행 하나를 저장하므로 미등록 `kings`를 조회할 행이 없어 `KeyError`가 납니다. CBOW는 주변 단어들로 중심 단어를 예측하고, Skip-gram은 중심 단어로 주변 단어를 예측합니다. 작은 인공 코퍼스에서는 유사도의 절대값이나 기대 순서가 안정적이지 않을 수 있습니다.

## 문제 6. `nn.Embedding`과 PAD 마스킹

```python
import torch
import torch.nn as nn

word_to_id = {
    "<PAD>": 0, "<OOV>": 1, "good": 2,
    "movie": 3, "not": 4, "bad": 5,
}
input_ids = torch.tensor([
    [2, 3, 0, 0],
    [4, 2, 3, 0],
    [5, 3, 0, 0],
])

embedding = nn.Embedding(
    num_embeddings=len(word_to_id),
    embedding_dim=4,
    padding_idx=0,
)
embedded = embedding(input_ids)
print(embedded.shape)               # (3, 4, 4)
assert torch.allclose(embedding.weight[2], embedded[0, 0])
assert torch.allclose(embedding.weight[0], torch.zeros(4))

mask = input_ids.ne(0).unsqueeze(-1)
masked_sum = (embedded * mask).sum(dim=1)
lengths = mask.sum(dim=1).clamp(min=1)
sentence_vectors = masked_sum / lengths
print(embedded.mean(dim=1)[0], sentence_vectors[0])
```

PAD 벡터가 0이어도 단순 평균은 PAD까지 포함한 전체 길이 4로 나누므로 실제 토큰 평균의 크기를 줄입니다. 마스크 평균은 PAD를 합과 분모 모두에서 제외합니다.

## 문제 7. 평균 임베딩 분류기

```python
labels = torch.tensor([1, 1, 0], dtype=torch.long)
linear_classifier = nn.Linear(4, 2)
criterion = nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(linear_classifier.parameters(), lr=0.05)

for epoch in range(100):
    optimizer.zero_grad()
    logits = linear_classifier(sentence_vectors.detach())
    loss = criterion(logits, labels)
    loss.backward()
    optimizer.step()
    if epoch % 20 == 0:
        print(epoch, loss.item())

with torch.no_grad():
    logits = linear_classifier(sentence_vectors)
    predictions = logits.argmax(dim=1)
print(logits.shape, predictions)
print((predictions == labels).float().mean().item())
```

`CrossEntropyLoss`는 내부에서 log-softmax를 안정적으로 계산하므로 로짓을 직접 전달합니다. 평균 풀링은 같은 벡터들의 합을 같은 수로 나누므로 `good movie`와 `movie good`을 구분하지 못합니다.

## 문제 8. 사전학습 임베딩 행 정렬과 동결

```python
pretrained = {
    "good": np.array([0.8, 0.1, 0.3, 0.5], dtype=np.float32),
    "movie": np.array([0.2, 0.4, 0.7, 0.1], dtype=np.float32),
    "bad": np.array([-0.7, 0.2, -0.4, 0.3], dtype=np.float32),
}

embedding_matrix = np.zeros(
    (len(word_to_id), 4),
    dtype=np.float32,
)
for word, token_id in word_to_id.items():
    if word in pretrained:
        embedding_matrix[token_id] = pretrained[word]

for word in ("<PAD>", "<OOV>", "not"):
    print(word, embedding_matrix[word_to_id[word]])

weights = torch.tensor(embedding_matrix)
frozen_embedding = nn.Embedding.from_pretrained(
    weights.clone(),
    freeze=True,
    padding_idx=0,
)
trainable_embedding = nn.Embedding.from_pretrained(
    weights.clone(),
    freeze=False,
    padding_idx=0,
)
print(frozen_embedding.weight.requires_grad)    # False
print(trainable_embedding.weight.requires_grad) # True
assert torch.allclose(
    trainable_embedding.weight[word_to_id["movie"]],
    torch.tensor(pretrained["movie"]),
)
```

행렬 shape가 맞더라도 행 순서가 현재 `word_to_id`와 어긋나면 오류 없이 다른 단어의 벡터를 조회합니다. 따라서 단어 문자열을 기준으로 현재 ID 행에 명시적으로 복사해야 합니다.

## 문제 9. FastText 문자 n-gram과 OOV

```python
from gensim.models import FastText

def char_ngrams(word, n=3):
    bounded = f"<{word}>"
    return {
        bounded[i:i + n]
        for i in range(len(bounded) - n + 1)
    }

apple_ngrams = char_ngrams("apple")
apples_ngrams = char_ngrams("apples")
print(apple_ngrams, apples_ngrams)
print("공통:", apple_ngrams & apples_ngrams)

common = dict(
    sentences=sentences,
    vector_size=20,
    window=2,
    min_count=1,
    sg=1,
    epochs=100,
    seed=42,
    workers=1,
)
word2vec_model = Word2Vec(**common)
fasttext_model = FastText(
    **common,
    min_n=3,
    max_n=6,
    bucket=10_000,
)

print("등록 여부:", {
    "Word2Vec": "apples" in word2vec_model.wv.key_to_index,
    "FastText": "apples" in fasttext_model.wv.key_to_index,
})
try:
    word2vec_model.wv.get_vector("apples")
except KeyError as error:
    print(type(error).__name__)

print(fasttext_model.wv.get_vector("apples").shape)
print(fasttext_model.wv.similarity("apple", "apples"))
print(fasttext_model.wv.similarity("apple", "queen"))
```

FastText의 `apples`도 등록 어휘는 아니지만 공유 문자 n-gram의 bucket 벡터를 합성해 벡터를 만들 수 있습니다. 이는 OOV를 완화할 뿐, 철자가 비슷한 두 문자열의 실제 의미가 같음을 보장하지 않습니다.

| --- | --- | --- |

## 문제 11. 정수·원-핫 인코딩

```python
from collections import Counter
import torch.nn.functional as F

tokenized = [["i", "love", "nlp"], ["i", "study", "nlp"]]
new_tokens = ["i", "enjoy", "nlp"]
counts = Counter(token for row in tokenized for token in row)
ordered = sorted(counts, key=lambda x: (-counts[x], x))

word_to_id_11 = {"<PAD>": 0, "<OOV>": 1}
word_to_id_11.update({
    word: index
    for index, word in enumerate(ordered, start=2)
})

def encode_11(tokens):
    return [word_to_id_11.get(token, 1) for token in tokens]

encoded_train = [encode_11(row) for row in tokenized]
encoded_new = encode_11(new_tokens)
one_hot = F.one_hot(
    torch.tensor([*encoded_train, encoded_new]),
    num_classes=len(word_to_id_11),
)
print(word_to_id_11, encoded_new, one_hot.shape)
assert encoded_new[1] == word_to_id_11["<OOV>"]
```

ID는 임베딩 또는 원-핫 열을 찾는 주소일 뿐 수치적 거리나 서열이 아닙니다.

## 문제 13. 코사인 유사도 직접 계산

```python
x = np.array([1, 2, 0], dtype=float)
y = np.array([2, 4, 0], dtype=float)
z = np.array([0, 0, 3], dtype=float)

def cosine(a, b):
    denominator = np.linalg.norm(a) * np.linalg.norm(b)
    if denominator == 0:
        raise ValueError("영벡터의 코사인 유사도는 정의되지 않습니다.")
    return (a @ b) / denominator

print(cosine(x, y))  # 1.0
print(cosine(x, z))  # 0.0
print(cosine_similarity(np.vstack([x, y, z])))
```

`y=2x`이므로 두 벡터의 방향은 같아 코사인 유사도가 1입니다. 코사인은 크기보다 방향을 비교하며, 영벡터는 norm이 0이라 직접 계산하면 0으로 나누게 됩니다.

## 문제 14. CBOW와 Skip-gram 쌍

```python
tokens = ["the", "royal", "queen", "smiles", "today"]
center_index = tokens.index("queen")
window = 2
context = [
    token
    for i, token in enumerate(tokens)
    if 0 < abs(i - center_index) <= window
]
skipgram_pairs = [("queen", token) for token in context]
cbow_pair = (context, "queen")
print(context)
print(skipgram_pairs)
print(cbow_pair)
```

문맥은 `the, royal, smiles, today`이고 Skip-gram은 4개 입력-정답 쌍, CBOW는 주변 목록 전체를 입력으로 하는 1개 쌍입니다. `window=2`는 앞뒤 두 문장이 아니라 중심 토큰으로부터 최대 두 토큰 위치를 뜻합니다.

## 문제 15. Word2Vec 설정 비교

## 문제 16. GloVe·Word2Vec·FastText

| 비교 기준 | Word2Vec | GloVe | FastText |
| --- | --- | --- | --- |
| 학습 신호 | 지역 문맥 예측 | 전역 단어 동시출현 통계 | 지역 문맥 예측 + 문자 n-gram |
| 기본 단위 | 등록 단어 | 등록 단어 | 단어와 문자 n-gram |
| OOV | 기본적으로 조회 불가 | 기본적으로 조회 불가 | n-gram으로 벡터 합성 가능 |
| 강점 | 단순하고 효율적인 의미 벡터 | 전역 통계를 직접 활용 | 형태 변화·오탈자·OOV 완화 |
| 주의점 | 문맥별 다의어 구분 불가 | 큰 동시출현 행렬 비용 | 철자 유사성을 과신할 수 있음 |

정적 임베딩은 문맥과 관계없이 한 등록 단어에 기본적으로 한 벡터를 줍니다. FastText OOV 벡터는 철자 조각을 합친 근사치이므로 새로운 단어의 실제 의미를 이해했다는 뜻은 아닙니다.

## 문제 17. PCA 시각화

```python
import matplotlib.pyplot as plt
from sklearn.decomposition import PCA

words = ["king", "queen", "prince", "man", "woman", "apple", "fruit"]
vectors = np.vstack([model.wv[word] for word in words])
pca = PCA(n_components=2)
coordinates = pca.fit_transform(vectors)

plt.scatter(coordinates[:, 0], coordinates[:, 1])
for word, (x_coord, y_coord) in zip(words, coordinates):
    plt.annotate(word, (x_coord, y_coord))
plt.show()
print(pca.explained_variance_ratio_)
print(pca.explained_variance_ratio_.sum())
```

PCA의 두 축은 원래 분산의 일부만 보존합니다. 따라서 2차원 투영에서 가까워 보인다는 사실이 원래 20차원 이웃 순위까지 그대로 보존함을 뜻하지 않습니다.


전체 모델은 학습 상태와 설정을 보존해 재학습·계속 학습할 때 알맞고, 벡터 전용 파일은 등록 단어의 추론 벡터만 가볍게 배포할 때 알맞습니다. FastText의 미등록 단어 합성에는 문자 n-gram bucket 가중치가 필요하므로 OOV 기능을 보존하려면 전체 FastText 모델을 저장해야 합니다.

## 문제 19. BERT의 문맥 표현

A의 `bank`는 금융기관, B의 `bank`는 강둑입니다. Word2Vec·GloVe·FastText는 기본적으로 등록 문자열 `bank`에 한 정적 벡터를 줍니다. BERT는 Self-Attention으로 각 위치가 주변 토큰을 반영하므로 두 `bank` 위치에 서로 다른 출력 벡터를 만들 수 있습니다.

## 문제 22. LDA

```python
from sklearn.decomposition import LatentDirichletAllocation

topic_docs = [
    "team scored a goal in the match",
    "player won the football match",
    "stock market price increased today",
    "investor bought shares in the market",
]
topic_vectorizer = CountVectorizer()
topic_counts = topic_vectorizer.fit_transform(topic_docs)
topic_words = topic_vectorizer.get_feature_names_out()

lda = LatentDirichletAllocation(
    n_components=2,
    random_state=42,
)
document_topics = lda.fit_transform(topic_counts)
for topic_index, weights in enumerate(lda.components_):
    top_ids = weights.argsort()[-5:][::-1]
    print(topic_index, topic_words[top_ids])
print(document_topics)
assert np.allclose(document_topics.sum(axis=1), 1)
```

LDA의 생성 모형은 단어 count를 관측 빈도로 사용하므로 보통 TF-IDF보다 비음수 count 행렬을 입력합니다. 여기서 LDA는 Latent Dirichlet Allocation이며 지도 분류의 Linear Discriminant Analysis와 이름의 약어만 같습니다.

## 문제 23. LSA와 LDA 비교

| 비교 기준 | LSA | LDA |
| --- | --- | --- |
| 입력 | Count 또는 TF-IDF 문서-단어 행렬 | 보통 Count 문서-단어 행렬 |
| 핵심 계산 | Truncated SVD | 확률적 생성 모형과 Dirichlet 사전분포 |

LSA 축은 분산·선형 결합으로, LDA 주제는 함께 나올 가능성이 큰 단어 분포로 얻어집니다. 둘 다 사람의 개념 이름을 자동으로 아는 것은 아니므로 상위 단어와 원문을 검토해 사람이 의미를 붙입니다.

## 문제 24. 선택 근거 검증 설계

첫 기준선은 빠르고 단어 계수 설명이 가능한 TF-IDF + 선형 분류기로 둡니다. FastText는 신규 검색어 18%의 OOV 완화 후보, Transformer는 문맥 성능 상한 후보로 두되 50ms 목표와 설명 가능성 비용을 실측합니다. 시간 순서 또는 사용자 중복을 고려해 train/validation/test를 분리하고, validation으로 전처리·모델을 고른 뒤 test는 한 번만 평가합니다. 클래스 불균형이면 macro F1과 클래스별 recall, 운영에는 p95 latency와 메모리도 함께 보고합니다. 학습 정확도는 과적합과 데이터 누수를 숨길 수 있어 채택 근거가 될 수 없습니다.

## 문제 29. TF-IDF 직접 계산

```python
N = len(documents)
```

## 문제 31. Word2Vec 입력 코퍼스

| 설정 | 의미 |
| --- | --- |
| `vector_size` | 단어 벡터 차원 |

## 문제 33. 한국어 Word2Vec 전처리

```python
import re
from konlpy.tag import Okt

reviews = [
    "영화가 정말 재밌었다!",
    "배우 연기는 좋지만 이야기가 지루해요.",
]
korean_stopwords = {"이", "가", "은", "는", "을", "를", "하지만"}
okt = Okt()
korean_sentences = []

for review in reviews:
    cleaned = re.sub(r"[^가-힣\s]", " ", review)
    cleaned = re.sub(r"\s+", " ", cleaned).strip()
    morphs = okt.morphs(cleaned, stem=True)
    tokens = [
        morph
        for morph in morphs
        if len(morph) > 1 and morph not in korean_stopwords
    ]
    if tokens:
        korean_sentences.append(tokens)
print(korean_sentences)
```

한국어는 조사·어미가 붙으므로 공백 분리만 하면 형태 변형이 서로 다른 단어가 되기 쉽습니다. 형태소 분석은 이를 완화하지만 오분석 가능성과 처리 비용이 있습니다. 부정어처럼 한 글자이거나 과업 의미를 바꾸는 기능어는 제거하면 안 되므로 불용어 규칙을 과업별로 검증합니다.

## 문제 36. Embedding과 원-핫 선형계층의 동치

```python
import torch.nn.functional as F

demo_embedding = nn.Embedding(6, 4)
token_id = torch.tensor(2)
one_hot_id = F.one_hot(token_id, num_classes=6)
via_matrix = one_hot_id.float() @ demo_embedding.weight

assert torch.allclose(via_matrix, via_lookup)
```

원-핫과 가중치의 곱은 1인 위치의 행만 남깁니다. `nn.Embedding`은 이 결과를 행 인덱싱으로 직접 얻으므로 거대한 원-핫 텐서를 만들고 대부분의 0과 곱할 필요가 없습니다.

## 문제 37. `MeanEmbeddingClassifier`

```python
class MeanEmbeddingClassifier(nn.Module):
    def __init__(
        self,
        vocabulary_size,
        embedding_dim,
        class_count,
        pad_id=0,
    ):
        super().__init__()
        self.pad_id = pad_id
        self.embedding = nn.Embedding(
            vocabulary_size,
            embedding_dim,
            padding_idx=pad_id,
        )
        self.classifier = nn.Linear(embedding_dim, class_count)

    def forward(self, token_ids):
        # (B, L) -> (B, L, E)
        embedded = self.embedding(token_ids)
        mask = token_ids.ne(self.pad_id).unsqueeze(-1)
        # (B, L, E) -> (B, E)
        summed = (embedded * mask).sum(dim=1)
        lengths = mask.sum(dim=1).clamp(min=1)
        sentence_vectors = summed / lengths
        # (B, E) -> (B, C)
        return self.classifier(sentence_vectors)

classifier = MeanEmbeddingClassifier(
    len(word_to_id),
    embedding_dim=4,
    class_count=2,
)
assert classifier(input_ids).shape == (3, 2)
```

평균은 교환법칙 때문에 `good movie`와 `movie good`처럼 토큰 구성만 같고 순서가 다른 문장을 같은 벡터로 만듭니다.

## 문제 58. 평가 함수

```python
def evaluate(model, data_loader):
    model.eval()
    total_loss = 0.0
    total_count = 0
    correct = 0
    all_predictions = []
    all_positive_probabilities = []
    criterion = nn.CrossEntropyLoss(reduction="sum")

    with torch.no_grad():
        for inputs, targets in data_loader:
            logits = model(inputs)
            probabilities = torch.softmax(logits, dim=1)
            predictions = logits.argmax(dim=1)
            total_loss += criterion(logits, targets).item()
            total_count += targets.numel()
            correct += (predictions == targets).sum().item()
            all_predictions.extend(predictions.tolist())
            all_positive_probabilities.extend(
                probabilities[:, 1].tolist()
            )

    print("긍정 확률:", all_positive_probabilities)
    return (
        total_loss / max(total_count, 1),
        correct / max(total_count, 1),
        all_predictions,
    )

evaluation_loader_58 = DataLoader(dataset_57, batch_size=2, shuffle=False)
print(evaluate(model_57, evaluation_loader_58))
```

한 클래스가 대부분인 불균형 데이터에서는 모든 샘플을 다수 클래스로 예측해도 accuracy가 높을 수 있으므로 macro F1, 클래스별 precision·recall, confusion matrix를 함께 봅니다.
