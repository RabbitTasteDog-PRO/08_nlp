# 텍스트 분류 문제 정답 및 해설

먼저 `텍스트분류복습.ipynb`을 직접 푼 뒤 비교하세요. 작은 데이터의 확률·loss·정확도는 모델 초기값과 라이브러리 버전에 따라 달라질 수 있습니다. 이 문서는 분류 문제마다 입력 표현, 로짓과 정답 shape, 데이터 누수 방지, 기준선과 평가 방법을 확인하는 용도입니다.

## 1. Naive Bayes와 TF-IDF

### 문제 1. CountVectorizer

```python
toy_texts = [
    "재미 감동 추천",
    "재미 유쾌 추천",
    "지루 실망 비추천",
    "지루 최악 비추천",
]
toy_labels = np.array(["긍정", "긍정", "부정", "부정"])

count_vectorizer = CountVectorizer()
toy_counts = count_vectorizer.fit_transform(toy_texts)
print(count_vectorizer.get_feature_names_out())
print(toy_counts.shape)
print(toy_counts.toarray())
```

행은 문서 4개, 열은 학습 어휘입니다. CountVectorizer는 단어 빈도만 저장하므로 토큰 순서가 바뀌어도 같은 벡터가 됩니다.

### 문제 2. Multinomial Naive Bayes

```python
new_texts = ["재미 추천", "지루 비추천", "재미 지루"]
nb_model = MultinomialNB(alpha=1.0)
nb_model.fit(toy_counts, toy_labels)

new_counts = count_vectorizer.transform(new_texts)
predictions = nb_model.predict(new_counts)
probabilities = nb_model.predict_proba(new_counts)
print("클래스 열 순서:", nb_model.classes_)
for text, prediction, probability in zip(
    new_texts,
    predictions,
    probabilities,
):
    print(text, prediction, dict(zip(nb_model.classes_, probability)))
```

`predict_proba`의 `j`번째 열은 `classes_[j]` 클래스의 확률입니다. 문자열 클래스의 배열 순서를 사람이 임의로 추정하지 말고 항상 `classes_`와 함께 읽습니다.

### 문제 3. Alpha 평활

```python
ambiguous = count_vectorizer.transform(["재미 지루"])
for alpha in (0.1, 10.0):
    current = MultinomialNB(alpha=alpha).fit(toy_counts, toy_labels)
    print("alpha:", alpha)
    print(dict(zip(
        current.classes_,
        current.predict_proba(ambiguous)[0],
    )))
    print(current.feature_log_prob_[0])
```

작은 alpha는 관찰 빈도를 강하게 반영해 미관찰 특성의 확률이 지나치게 작아질 수 있고, 큰 alpha는 클래스별 단어 차이를 과도하게 평평하게 만들어 underfitting할 수 있습니다. Alpha는 epoch가 아니라 additive smoothing의 강도입니다.

### 문제 4. TF-IDF fit과 transform

```python
train_docs = [
    "space rocket orbit",
    "hockey goal team",
    "election policy vote",
]
test_docs = ["rocket team", "policy orbit"]

tfidf_vectorizer = TfidfVectorizer()
X_train = tfidf_vectorizer.fit_transform(train_docs)
X_test = tfidf_vectorizer.transform(test_docs)
print(X_train.shape, X_test.shape)
print(tfidf_vectorizer.get_feature_names_out())
extra_test = tfidf_vectorizer.transform(["policy unseenword"])
print(extra_test.toarray())
```

`unseenword`는 학습 어휘에 없어 벡터에 새 열을 만들지 않고 무시됩니다. Test에 다시 fit하면 test의 어휘와 DF/IDF 정보가 모델 입력 설계에 들어가 평가가 낙관적으로 되는 데이터 누수이며 train/test의 열 의미도 달라집니다.

기준선은 학습 없이도 얻는 점수를 넘어섰는지 확인하는 최소 비교점입니다. 여기서는 클래스마다 학습 예제가 한 개뿐이므로 test 두 개의 점수로 우열을 일반화할 수 없습니다.

## 2. LSTM 순차 분류

### 문제 7. PAD·OOV 사전

```python
train_sentences = [
    "movie was very good",
    "movie was very boring",
    "acting was good",
]
train_tokens = [sentence.lower().split() for sentence in train_sentences]
token_counts = Counter(
    token
    for sentence in train_tokens
    for token in sentence
)
ordered_tokens = sorted(
    token_counts,
    key=lambda token: (-token_counts[token], token),
)
PAD_ID, OOV_ID = 0, 1
word_to_id = {"<PAD>": PAD_ID, "<OOV>": OOV_ID}
word_to_id.update({
    token: index
    for index, token in enumerate(ordered_tokens, start=2)
})
print(word_to_id)
```

ID는 임베딩 표의 행 주소입니다. 빈도순으로 배정했더라도 ID 크기 자체가 단어 의미·중요도의 크기는 아닙니다.

### 문제 8. OOV와 post-padding

```python
new_sentences = [
    "movie was good",
    "unknown word was amazing",
]
MAX_LENGTH = 6

def encode_and_pad(text):
    ids = [
        word_to_id.get(token, OOV_ID)
        for token in text.lower().split()
    ][:MAX_LENGTH]
    actual_length = max(len(ids), 1)
    if not ids:
        ids = [OOV_ID]
    return (
        ids + [PAD_ID] * (MAX_LENGTH - len(ids)),
        actual_length,
    )

encoded = [encode_and_pad(text) for text in new_sentences]
token_ids = torch.tensor(
    [ids for ids, _ in encoded],
    dtype=torch.long,
)
lengths = torch.tensor(
    [length for _, length in encoded],
    dtype=torch.long,
)
print(token_ids, token_ids.shape)  # (2, 6)
print(lengths, [len(row) for row in token_ids])
```

실제 길이는 각각 3과 4이고 PAD 포함 길이는 모두 6입니다. `unknown`, `word`, `amazing`은 같은 OOV ID를 공유합니다.

### 문제 9. TensorDataset과 DataLoader

```python
labels = torch.tensor([1, 0], dtype=torch.long)
dataset = TensorDataset(token_ids, labels)
loader = DataLoader(dataset, batch_size=2, shuffle=True)
batch_ids, batch_labels = next(iter(loader))
print(batch_ids.shape, batch_labels.shape)  # (2, 6), (2,)
```

`B`는 한 mini-batch의 문서 수입니다. 전체 데이터 수가 batch size로 나누어떨어지지 않으면 마지막 batch가 더 작습니다. Train의 shuffle은 epoch마다 배치 구성과 순서 편향을 줄입니다.

### 문제 10. `nn.Embedding`

```python
embedding = nn.Embedding(
    len(word_to_id),
    4,
    padding_idx=PAD_ID,
)
embedded = embedding(token_ids)
print(token_ids.shape, embedded.shape)  # (B,L) -> (B,L,E)
assert torch.allclose(
    embedded[0, 0],
    embedding.weight[token_ids[0, 0]],
)
```

토큰 ID는 임베딩 행을 선택하고 각 위치에 길이 `E=4` 벡터를 놓습니다. PAD 위치도 출력 Tensor에 남아 shape를 유지하며, `padding_idx`는 그 행의 gradient 갱신을 막는 설정입니다.

### 문제 11. PackedSequence

```python
lengths = token_ids.ne(PAD_ID).sum(dim=1).clamp(min=1)
embedded = embedding(token_ids)
packed = pack_padded_sequence(
    embedded,
    lengths.cpu(),
    batch_first=True,
    enforce_sorted=False,
)
print(lengths)
print(packed)
```

`batch_first=True`는 입력을 `(B,L,E)`로 해석하고, `enforce_sorted=False`는 길이 내림차순으로 미리 정렬하지 않은 배치를 허용합니다. PackedSequence는 단순히 펼친 1차원 Tensor가 아니라 각 step의 유효 batch 크기 정보로 PAD 계산을 건너뛰게 하는 표현입니다.

### 문제 12. LSTM 분류기

```python
class ReviewLSTMClassifier(nn.Module):
    def __init__(
        self,
        vocabulary_size,
        embedding_dim=4,
        hidden_dim=8,
        num_classes=2,
        pad_id=0,
    ):
        super().__init__()
        self.pad_id = pad_id
        self.embedding = nn.Embedding(
            vocabulary_size,
            embedding_dim,
            padding_idx=pad_id,
        )
        self.lstm = nn.LSTM(
            embedding_dim,
            hidden_dim,
            batch_first=True,
        )
        self.classifier = nn.Linear(hidden_dim, num_classes)

    def forward(self, input_ids):
        lengths = input_ids.ne(self.pad_id).sum(dim=1).clamp(min=1)
        embedded = self.embedding(input_ids)
        packed = pack_padded_sequence(
            embedded,
            lengths.cpu(),
            batch_first=True,
            enforce_sorted=False,
        )
        _, (hidden, _) = self.lstm(packed)
        return self.classifier(hidden[-1])

lstm_model = ReviewLSTMClassifier(len(word_to_id))
print(lstm_model(token_ids).shape)  # (2, 2)
```

`hidden_dim=8`은 LSTM 층 개수가 아니라 각 문장을 요약하는 hidden 벡터의 특성 길이입니다.

### 문제 13. 순전파 shape

```python
lengths_13 = token_ids.ne(PAD_ID).sum(dim=1).clamp(min=1)
embedded_13 = lstm_model.embedding(token_ids)
packed_13 = pack_padded_sequence(
    embedded_13,
    lengths_13.cpu(),
    batch_first=True,
    enforce_sorted=False,
)
_, (hidden_13, _) = lstm_model.lstm(packed_13)
sentence_vectors_13 = hidden_13[-1]
logits_13 = lstm_model.classifier(sentence_vectors_13)

print(token_ids.shape)            # (B, L)
print(embedded_13.shape)          # (B, L, E)
print(sentence_vectors_13.shape)  # (B, H)
print(logits_13.shape)            # (B, C)
assert torch.allclose(logits_13, lstm_model(token_ids))
```

로짓은 클래스별 정규화 전 점수로 합이 1일 필요가 없습니다. `model(token_ids)`는 `nn.Module.__call__`의 hook 처리를 거쳐 내부 `forward()`를 호출하므로 보통 `forward()`를 직접 부르지 않습니다.

### 문제 16. 학습·검증과 최적 상태

```python
def train_one_epoch(model, loader, optimizer, criterion):
    model.train()
    total_loss = 0.0
    total_count = 0
    for input_ids, targets in loader:
        optimizer.zero_grad()
        logits = model(input_ids)
        loss = criterion(logits, targets)
        loss.backward()
        optimizer.step()
        total_loss += loss.item() * targets.size(0)
        total_count += targets.size(0)
    return total_loss / max(total_count, 1)

def evaluate(model, loader, criterion):
    model.eval()
    total_loss = 0.0
    targets_all, predictions_all = [], []
    with torch.no_grad():
        for input_ids, targets in loader:
            logits = model(input_ids)
            total_loss += criterion(logits, targets).item() * targets.size(0)
            targets_all.extend(targets.tolist())
            predictions_all.extend(logits.argmax(dim=1).tolist())
    return (
        total_loss / max(len(targets_all), 1),
        f1_score(
            targets_all,
            predictions_all,
            average="macro",
            zero_division=0,
        ),
    )

best_validation_loss = float("inf")
best_state = None
history = []
for epoch in range(20):
    train_loss = train_one_epoch(
        lstm_model, train_loader, optimizer, criterion
    )
    validation_loss, validation_f1 = evaluate(
        lstm_model, validation_loader, criterion
    )
    history.append((train_loss, validation_loss, validation_f1))
    if validation_loss < best_validation_loss:
        best_validation_loss = validation_loss
        best_state = copy.deepcopy(lstm_model.state_dict())

if best_state is not None:
    lstm_model.load_state_dict(best_state)

overfit_candidates = [
    epoch
    for epoch in range(1, len(history))
    if history[epoch][0] < history[epoch - 1][0]
    and history[epoch][1] > history[epoch - 1][1]
]
print(overfit_candidates)
```

`validation_loader`는 train과 분리된 자료여야 합니다. Train loss 감소와 validation loss 상승이 반복되면 과적합 신호이며 한 epoch의 우연한 변동과 구분해 봅니다.

## 3. 멀티레이블 분류

### 문제 17. Multi-hot 정답

```python
from sklearn.preprocessing import MultiLabelBinarizer

label_lists = [
    ("판타지", "모험"),

print(mlb.classes_, Y, Y.shape)
```

한 문서에 두 label이 동시에 참이므로 하나의 class ID를 고르는 대신 각 열의 포함 여부를 독립적으로 표시합니다.

### 문제 18. X·Y 인덱스 정렬

```python
texts = [
```

`y_test=Y[train_indices]`를 쓰면 X test 1행과 Y 3행이 달라 즉시 shape 오류가 나거나, 행 수가 우연히 같다면 더 위험하게 문장과 정답이 잘못 짝지어집니다.

### 문제 20. 독립 확률과 threshold

```python
threshold_predictions = {}
for threshold in (0.3, 0.5, 0.7):
    predicted = (test_probabilities >= threshold).astype(int)
    threshold_predictions[threshold] = predicted
    print(threshold, predicted, predicted.sum(axis=1).mean())
```

각 열은 독립 이진 확률이므로 한 행의 합이 1일 필요가 없고 여러 label 또는 label 0개가 선택될 수 있습니다. 단일 label softmax는 상호 배타 클래스의 합을 1로 만들고 하나를 고르는 반면, 멀티레이블은 label별 sigmoid 확률과 threshold를 사용합니다.

### 문제 21. 멀티레이블 지표

```python
predicted_05 = threshold_predictions[0.5]
print(f1_score(
    y_test, predicted_05, average="micro", zero_division=0
))
print(f1_score(
    y_test, predicted_05, average="macro", zero_division=0
))
print(hamming_loss(y_test, predicted_05))
```

Micro F1은 모든 label 판단을 합쳐 빈도가 큰 label의 영향이 크고, macro F1은 label별 F1을 동일 가중 평균해 희귀 label 실패를 드러냅니다. 어떤 label의 정답 또는 예측 양성이 하나도 없으면 precision·recall 분모가 0이 될 수 있어 `zero_division=0`을 명시합니다. Hamming loss는 전체 문서-label 칸 중 잘못 판단한 비율이라 낮을수록 좋습니다.

### 문제 22. 레이블 비율 기준선

```python
label_prevalence = y_train.mean(axis=0)
baseline_row = (label_prevalence >= 0.5).astype(int)
baseline_predictions = np.repeat(
    baseline_row[None, :],
    repeats=len(y_test),
    axis=0,
)

def multilabel_metrics(targets, predictions):
    return {
        "micro_f1": f1_score(
            targets, predictions,
            average="micro", zero_division=0,
        ),
        "macro_f1": f1_score(
            targets, predictions,
            average="macro", zero_division=0,
        ),
        "hamming_loss": hamming_loss(targets, predictions),
    }

print(label_prevalence)
print("baseline:", multilabel_metrics(y_test, baseline_predictions))
print("model:", multilabel_metrics(y_test, predicted_05))
```

Threshold를 test에서 고르면 test 정답에 맞춘 하이퍼파라미터가 되어 점수가 편향됩니다. 별도 validation에서 전체 threshold 또는 label별 threshold를 고정한 뒤 test를 한 번만 평가합니다.

```python
reviews = [
    "영화 정말 재미 있다",
    "연출 매우 지루 하다",
    "배우 연기 좋다",
    "결말 너무 나쁘다",
]
review_tokens = [review.split() for review in reviews]
review_vocabulary = sorted({
    token for row in review_tokens for token in row
})
cnn_word_to_id = {"<PAD>": 0, "<OOV>": 1}
cnn_word_to_id.update({
    token: index
    for index, token in enumerate(review_vocabulary, start=2)
})

def cnn_encode(text, max_length=6):
    ids = [
        cnn_word_to_id.get(token, 1)
        for token in text.split()
    ][:max_length]
    return ids + [0] * (max_length - len(ids))

cnn_input_ids = torch.tensor(
    [cnn_encode(review) for review in reviews],
    dtype=torch.long,
)
cnn_embedding = nn.Embedding(
    len(cnn_word_to_id), 4, padding_idx=0
)
cnn_embedded = cnn_embedding(cnn_input_ids)
print(cnn_input_ids.shape)  # (4, 6)
print(cnn_embedded.shape)   # (4, 6, 4)
```

토큰화·PAD·OOV 규칙이 바뀌면 같은 ID가 다른 토큰을 뜻하거나 학습에 없던 열 계약이 생기므로 train에서 정한 규칙을 추론까지 고정합니다.

### 문제 24. Conv1d 축과 출력 길이

```python
conv_input = cnn_embedded.transpose(1, 2)
conv2 = nn.Conv1d(4, 3, kernel_size=2)

features2 = conv2(conv_input)
```

Padding과 dilation이 기본값일 때 위치 길이는 `L-k+1`입니다. Conv1d는 두 번째 축을 입력 channel로 해석하므로 임베딩 차원 `E`가 channel, 토큰 위치 `L`이 합성곱 이동 축이 되도록 전치합니다.

```python
activated = torch.relu(features2)
```

### 문제 26. 병렬 커널 TextCNN

```python
class TextCNNClassifier(nn.Module):
    def __init__(
        self,
        vocabulary_size,
        embedding_dim=4,
        filter_count=4,
        kernel_sizes=(2, 3, 4),
        class_count=2,
        pad_id=0,
        dropout=0.3,
    ):
        super().__init__()
        self.embedding = nn.Embedding(
            vocabulary_size,
            embedding_dim,
            padding_idx=pad_id,
        )
        self.convolutions = nn.ModuleList([
            nn.Conv1d(
                embedding_dim,
                filter_count,
                kernel_size,
            )
            for kernel_size in kernel_sizes
        ])
        self.dropout = nn.Dropout(dropout)
        self.classifier = nn.Linear(
            filter_count * len(kernel_sizes),
            class_count,
        )

    def forward(self, input_ids):
        embedded = self.embedding(input_ids)      # (B,L,E)
        convolution_input = embedded.transpose(1, 2)  # (B,E,L)
        pooled = [
            torch.relu(convolution(convolution_input))
            .max(dim=2).values
            for convolution in self.convolutions
        ]
        features = torch.cat(pooled, dim=1)       # (B,4*3)
        return self.classifier(self.dropout(features))

textcnn = TextCNNClassifier(len(cnn_word_to_id))
print(textcnn(cnn_input_ids).shape)  # (4, 2)
```

각 세 kernel이 4개 filter 값을 내므로 concat 특성은 `4 × 3 = 12`입니다.

### 문제 27. TextCNN 학습·평가

```python
cnn_labels = torch.tensor([1, 0, 1, 0], dtype=torch.long)
cnn_criterion = nn.CrossEntropyLoss()
cnn_optimizer = torch.optim.Adam(textcnn.parameters(), lr=0.01)

for epoch in range(100):
    textcnn.train()
    cnn_optimizer.zero_grad()
    logits = textcnn(cnn_input_ids)
    loss = cnn_criterion(logits, cnn_labels)
    loss.backward()
    cnn_optimizer.step()

textcnn.eval()
with torch.no_grad():
    cnn_logits = textcnn(cnn_input_ids)
    cnn_predictions = cnn_logits.argmax(dim=1)
    cnn_accuracy = (
        cnn_predictions == cnn_labels
    ).float().mean().item()

majority_count = torch.bincount(cnn_labels).max().item()
majority_accuracy = majority_count / len(cnn_labels)
print(cnn_accuracy, majority_accuracy)
```

Train의 Dropout은 무작위 특성 의존을 줄이는 정규화이며 eval에서는 끄므로 예측이 안정됩니다. 이 코드는 학습 자료 자체를 평가하므로 일반화 점수가 아니며, 별도 validation에서 최빈 클래스 기준선과 macro F1을 비교해야 합니다.

### 문제 29. 모델 선택 보고서

| 상황 | 기준선·후보 | 입력 → 출력 / 정답 | 주요 평가 | 큰 위험 |
| --- | --- | --- | --- | --- |
| 근거 단어 문의 분류 | Count/TF-IDF + Naive Bayes | `(B,V) → (B,C)` / class ID | macro F1, 클래스 recall, calibration | 누수, 계수를 인과 근거로 오해 |
| 순서·긴 문맥 뉴스 분류 | TF-IDF 기준선 → LSTM | `(B,L) IDs → (B,C)` / class ID | macro F1, confusion matrix | 긴 문맥 잘림, OOV, 과적합 |
| 여러 영화 장르 tag | label 비율 기준선 → One-vs-Rest | TF-IDF `(B,V) → (B,K)` / multi-hot | micro/macro F1, Hamming loss | label 불균형, test에서 threshold 선택 |
| 짧은 감성 표현 대량 리뷰 | Naive Bayes 기준선 → TextCNN | `(B,L) IDs → (B,2)` / class ID | accuracy, macro F1, latency | OOV, kernel보다 짧은 입력, 과적합 |

간단한 모델은 데이터·전처리·평가 파이프라인의 오류를 빠르고 싸게 드러내며 복잡한 모델의 실제 개선 폭을 측정하게 합니다. 복잡도가 늘면 성능 가능성뿐 아니라 학습·서빙 비용, 설명 어려움과 장애 지점도 늘어나므로 요구사항을 충족하는지 실측한 뒤 채택합니다.
